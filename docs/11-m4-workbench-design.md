# 11 M4 知识与Agent工作台设计

> v0.3；2026-11-01。上游：[需求](01-requirements.md)、[M3本机条件验收](acceptance/M3-acceptance.md)、[阶段计划](03-milestones.md)。T01a共享会话及T01b首轮任务写交互已实现，知识管理及其余为待实施设计。

## 1. 目标和保留边界

让使用者通过正式中文界面完成数据核对、任务观察、补充信息、受控知识引用及人工复核；不要求读原始JSON。现有基础分析/工具/比较页面继续使用，模型实验保持独立开发标记。页面只消费授权API，不能自己生成证据、判断发布资格、选择供应商密钥或自动确认输入。

M3的输出是未发布草稿。M4不能以“模型已完成”替代工程复核，不能把相似度当故障概率、缺少证据当健康、比较差值当维修有效。原始完整M3语义/四分类及M6工厂准入仍未通过。

## 2. 页面和会话组织

正式应用共享一个登录会话与CSRF处理，保留现有Cookie/同源API机制；先提取现有useFormalWorkbench中的身份生命周期，避免各页独立维护身份或互相覆盖会话。组织/用户名可保留当前本机缓存策略；密码、API key不进入浏览器持久存储。

| 页面 | 主要任务 | 首轮归属 |
| --- | --- | --- |
| 数据分析 | 上传CSV、核对当前参数/输入确认、基础图表、工具和比较 | 复用既有M1/M2 |
| Agent任务 | 本人任务分页、状态/执行模式、输入、问题、调用、来源、草稿和有效性 | M4-T01a/T01b |
| 知识资料 | MD/TXT导入、版本、来源、适用范围、提交/审核发布/撤回和索引状态 | M4-T02 |
| 报告复核 | 草稿整理、版本及复核身份/理由，接受/修改/退回和导出 | M4-T03/T04，需补正式服务 |
| 授权与设置 | 知识审核授权和后续账号/设备范围设置 | M4-T05，服务端权限为准 |

App先采用清楚的模块导航，不为此次切页引入路由/状态库等新依赖。未交付入口不展示为可用功能。现有“模型实验（开发）”不能成为正式任务API的隐式替代。

## 3. M4-T01a：先交付正式任务只读切片

交付顺序：共享会话 → 本人任务列表 → 详情/有效性 → 来源入口 → 状态与错误验证。第一切片不提供创建/恢复/取消按钮，也不伪造演示任务；无数据时说明后续创建入口尚待实施，已有正式后端任务可被本人查询。

规划文件：frontend/src/features/agent-tasks/types.ts、api.ts、useAgentTasks.ts、AgentTaskWorkbench.vue；共享会话位于frontend/src/composables/useSession.ts。现有数据分析组件继续保留，不同时重写图表或数值工具。模块类型、API和状态与展示分开。

使用现有GET /api/v1/agent-tasks?page=&page_size=和GET /api/v1/agent-tasks/{id}。列表只有当前发起人任务，不提供“组织所有任务”假筛选。历史选择按组织/用户隔离；切换账号、退出或会话失效立即清空数据和待处理请求，旧响应不能覆盖新身份页面。

详情首屏显示目标、当前状态、输入版本、执行模式、是否调用模型/Embedding、当前有效性和主要缺项；模型/图内部版本、预算、账本、事件及脱敏校验诊断放可展开的取证明细。draft为空或draft_validity不可用时不显示缓存草稿为当前结论。时间字段不存在时显示未记录，不由前端补造持续时间。

来源展示优先读取服务端当前可访问引用。数值来源可导航已有基础/工具结果；知识块显示原文与来源锚点，普通文本渲染，不执行HTML或资料中的链接/指令。首次来源跳转无法完成时明确标“详情入口待接入”，不展示假详情。

## 4. 状态和异步行为

| 服务端状态/条件 | 页面表达 | 后续动作原则 |
| --- | --- | --- |
| queued/running | 排队/执行中，最后一次确认状态 | 详情轮询，切页/身份变化停止；不显示已生成结论 |
| waiting_information | 等待指定信息，展示服务端问题和允许选择 | T01b按question_id/expected_version提交，不自造选项 |
| interrupted | 中断及可恢复原因、已有调用/预算 | T01b显式恢复；不是浏览器自动重跑 |
| completed | 本任务流程已完成 | 仍检查未发布草稿及有效性，不等于诊断确认 |
| completed_degraded | 受限完成，突出缺项 | 允许查看已有可用来源，不隐藏限制 |
| refused | 证据不足或无法支持 | 显示缺项/错误，不生成替代答案 |
| failed/timed_out/budget_exhausted | 失败/超时/预算耗尽 | 保留失败信息；不无限重试 |
| cancelled/superseded | 已取消/输入已被替代 | 不恢复为运行中，不沿用旧确认 |
| draft_validity失效 | 历史草稿不可作为当前依据 | 清除已展示正文，说明当前状态 |
| 401/403/404/409/429/网络未知 | 登录失效/权限不足或资源不可见/版本冲突/容量/状态未确认 | 清空无权数据、重新查询当前状态；不推断任务失败或成功 |

T01a轮询仅对本页当前活跃详情，正常2秒、容量/暂时网络错误退避，页面隐藏时暂停，不并发堆积请求；采用AbortController与请求序号防迟到覆盖。普通GET可显式刷新，POST响应未知不能生成新幂等键自动重发。

## 5. T01b及后续写操作

创建任务使用结构化goal及真实measurement_revision_id/比较声明/knowledge_scope。描述用于任务上下文，不擅自把自然语言解释成确认或维修授权。未确认输入仍由正式数据页面人工确认；任务挂起不由模型代确认。

POST创建、resume、cancel沿用Idempotency-Key，恢复/取消携带最新expected_version，恢复另带原question_id与明确答案。保留未确认响应的原键和请求体，先查询或重放同一命令，409后读取当前版本并由用户决定。暂停、取消或浏览器离开不能抹去服务端预算/调用账本。

知识页面严格区分草稿、待审、发布、撤回、索引ready/failed/身份不匹配；发布和索引是两步，建库失败保留原活动索引的事实由服务端返回。开发测试资料默认排除，网页不提供越过include_developer门槛的普通查询开关。审核授权不等于资料已获独立工程认证。

正式报告版本/接受修改退回/工单服务尚未实现，不复用Agent draft当已发布报告。M4-T03建立其独立状态和不可变版本，M5再绑定确认、审批、工单及复测，不提前做“自动派工”按钮。
