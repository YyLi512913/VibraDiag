## 阅读说明与优先级

项目独立设计开发，首发支持定速稳态电机滚动轴承的离线加速度 CSV 分析。MD/TXT 是知识库资料入口。面向工厂试用的最终交付版须完成本文全部 P0 需求；中间开发版本可逐步交付，但不能称为已满足试用准入。

- P0：试用准入必须完成，除明确标为 P1 的功能外，本文要求均属 P0。
- P1：可后续增强，不阻断首发受控试用，例如 PDF 知识导入、批量多文件分析、交互选段。
- 明确不做的项目见第 4 节。未实测的能力不得记为验收通过。
- 故事编号沿用历史 A—E，新增 F—I；正文按“导入 → 关联 → 分析与 Agent → 报告 → 工单 → 支撑功能”阅读。

### 开发重点与先后顺序

本项目是以诊断 Agent 为核心的全栈应用。完整需求描述最终试用范围，不表示先开发全部管理功能再实现 Agent。

1. 优先验证核心：确定性分析工具、Agent 按证据选择下一工具、多假设取证与冲突处理、引用校验、拒答和有界恢复；用最小上传/对话/图表/证据页面展示实际执行。
2. 再形成业务闭环：报告复核、轻量设备关联、内部工单和复测；不扩展成通用维修管理平台。
3. 最后完成试用准入：细化授权、审计与管理界面、部署备份、压力与故障恢复验收；身份/资源/版本等跨模块约束在总体设计阶段预先纳入，不能临近交付才补数据边界。

早期无完整权限的开发版本仅监听本机，不接真实共享试用。完整 P0 的交付门槛不变；复杂大屏、通用审批引擎和额外后台模块不加入首发。

Agent 验收必须包含“同一入口、不同证据触发不同工具路径”的案例。固定串行执行所有工具后让模型润色报告，不能单独作为核心 Agent 能力验收通过。

## 1. 角色

| 角色 | 职责 | 主要界面 |
| --- | --- | --- |
| 点检员 | 导入数据、描述现象、补充采集信息，查看授权设备记录 | 数据入口与对话窗口 |
| 维修工程师 | 维护台账、运行分析与诊断、复核报告、确认普通工单及复测 | 诊断工作台 |
| 设备主管 | 查看授权设备报告、审批高优先级工单、管理业务处理 | 设备与工单列表 |
| 系统管理员 | 管理账号、授权、模型配置、部署与备份 | 管理设置 |

账号可被明确授予多个角色；管理员身份不自动授予诊断复核或工单审批权限。单工厂内仍须有后端资源访问控制，不能仅隐藏前端按钮。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| 设备 | 台账中的一台目标设备，有组织内唯一标识；显示名可修改，历史引用不随之改变 |
| 测点 | 传感器安装位置标识，例如驱动端 DE / 风扇端 FE；不等同于故障所在部件 |
| 测量方向 | 测点的测量轴向，例如水平径向、垂直径向、轴向或明确标注的其他方向；不得从波形猜测 |
| 目标轴承 | 该次轴承分析关注的部件位置；同一测点可能接收到其他部件振动，测点位置不直接证明故障位置 |
| 工况 | 转速与负载的组合，诊断结论必须绑定工况 |
| 特征频率 | BPFO 外圈、BPFI 内圈、BSF 滚动体、FTF 保持架 |
| 证据 ID | EV-xxx，唯一标识一条证据，可解析到信号片段或标准条款 |
| 诊断会话 | 一次现象描述到结论的全过程，可跨请求恢复 |

## 3. 用户故事与验收标准

### 场景 D：振动数据导入

说明：D 用于保持历史 A—C 编号稳定；实际业务顺序中，数据导入先于信号分析和诊断。用户可先上传文件，也可从对话入口进入上传流程，两个入口使用同一份数据记录。

**US-D1 上传 CSV 与填写采样参数**

作为点检员或维修工程师，我希望上传已有振动 CSV 并明确采样参数，以便系统基于正确的时间轴与单位进行分析。

- 第一版支持 CSV 加速度数据；不将 MD 手册当作振动采样文件处理。
- 首版模板：UTF-8（允许 BOM）、单列 `value`、每行一个采样值，代表一个测点的一个方向；页面提供模板下载和填写说明。不支持混合列、重复表头和内部空行；允许文件结束换行。
- 导入页面必须包含采样率和加速度单位。首版单位为 `g`、`m/s²`，界面说明是加速度单位，不接受单位含义不清的输入。
- 第一版由用户填写参数；若未来加入元数据读取，须展示来源并由用户核对。不从文件名、信号幅值或模型猜测参数。
- 采样率缺失、非有限正数，或单位缺失、不在支持范围内时，阻止进入分析并定位对应字段；已选择的文件与其他有效输入保留。
- 尚未提供设备、测点或转速时可以完成文件与基础采样参数校验；不得因此捏造这些信息。后续任务必要条件见场景 E。

**US-D2 文件校验与错误提示**

作为上传人员，我希望系统明确指出文件问题，以便修正后重试，而不是收到空图或通用报错。

- 后端验证文件内容，不仅检查扩展名。空文件、无法解码、表头不符、非数值、NaN/Inf 和点数不足时拒绝分析。
- 对可定位的数据问题说明原因及行号；保留原始内容，不静默删除数据点、不跳过若干表头行、不截取部分文件冒充全量分析。
- 大幅值采样不能仅因超出固定阈值就删除；缺少量程信息时不声称确认传感器过载。
- 首版每文件最多 32 MiB，1024—1000000 个采样点；两项限制同时生效，超限不静默截断，提示限制及可获知的当前值。限额调整需重新做资源验证并更新配置版本。
- 参数或内容错误返回可识别的输入错误；失败不能返回“分析成功但无结果”。未知内部错误提供请求标识供排查，不向用户展示堆栈。

**US-D3 导入确认与记录追溯**

作为维修工程师，我希望确认将被分析的数据和参数，并在以后找到同一份数据，以便复核诊断依据。

- 文件通过检查后展示文件名、采样点数、采样率、加速度单位、记录时长和简短波形预览；预览抽样不得改变分析数据。
- 用户确认后发起分析；“文件已导入”和“诊断已完成”分别展示，不能混为同一状态。
- 保存原文件、文件校验值、上传人员、上传时间与采样参数，并赋予唯一数据记录 ID。
- 原文件名只作显示用途，不能直接作为服务器存储路径。
- 采集时间与上传时间分别记录；未提供采集时间时显示未知，不以当前时间替代。
- 后续修改采样参数形成有记录的新版本，已有分析结果保留原参数，不能被新参数静默覆盖。

**本场景验收示例**

| 输入或操作 | 预期行为 |
| --- | --- |
| 合法 CSV、4096 Hz、m/s² | 检查通过，显示样本信息，可确认进入分析 |
| 同一文件未填采样率 | 提示缺失，不默认按 1024 Hz 分析 |
| 采样率为 0 或单位未填写 | 阻止分析并指出字段 |
| 文件某行包含文本、NaN 或 Inf | 明确提示问题，不删除后继续计算 |
| 空文件或过短信号 | 给出数据不足提示，不返回空成功 |
| 将 MD 手册上传到振动入口 | 提示此入口接收 CSV，并指引至独立知识库入口 |
| 原文件名包含路径片段 | 不得使文件写入存储目录之外 |
| 导入成功后修改单位 | 保留修改记录，已有结果不被静默改变 |

### 场景 E：设备、测点与工况关联

目标：让系统明确“哪份信号、来自哪里、在什么条件下采集、哪些条件已经核实”，同时允许信息逐步补齐。E 沿用独立编号，不改变历史故事编号。

**US-E1 设备与测点台账**

作为维修工程师，我希望维护简单的设备、部件和测点信息，并在上传时选择，以便减少重复填写和错误关联。

- 设备至少具有组织内唯一标识、显示名称和设备类型；首发只对支持范围内的设备提供专门诊断。
- 设备下可建立部件位置及测点，测点方向分别记录。原始单列 CSV 对应一条测点方向通道，不把同文件任意列自动拼成多个部件。
- 设备额定转速属于台账参考值，不能自动当作每次采集的实测转速。对设备台账更新不回写历史分析快照。
- 可将轴承参数绑定到具体部件，保留来源与版本。参数修改只影响明确采用新版本的任务。
- 首版提供列表、详情与必要的维护操作，不要求先完成实时设备大屏、地图或健康预测。
- 具有写权限的人员才可维护台账，权限见场景 G。已被数据引用的设备和测点可停用，不直接删除历史关联。

**US-E2 导入与现象描述中的数据关联**

作为上传人员，我希望在导入时关联设备和测点，也能先保存未分配的数据，以便整理文件时不被缺失台账阻断。

- 支持“选择已有设备和测点”和“先保存为待关联数据”两条路径。创建新台账使用独立操作，不因上传自动生成不存在的现场设备。
- 待关联数据可在拥有访问权限的工作区进行基础信号分析，报告明确显示关联未核实；不能挂到某台设备的健康趋势或生成针对该设备的维修工单。
- 从设备详情页发起上传时可预填设备和测点，但必须可见、可核对，不能后台静默关联。
- 通过对话表达设备时，系统只列出当前用户有权访问的候选；有重名或多个测点时要求选择，不凭名称猜测唯一设备。
- 原始信号、采样参数版本、设备关联版本与一次分析任务分别保留。关联修正不能让已有报告看起来从未发生过修改。
- 公开数据可以作为明确标识的测试资产导入；仿真台账和测试报告不混入实际设备的记录。

**US-E3 按任务检查必要条件**

作为维修工程师，我希望缺少信息时仍能完成有依据的分析，并清楚看到不能执行的项目及补充方式。

| 任务 | 必要条件 | 条件不足时的行为 |
| --- | --- | --- |
| 文件解析与基础分析 | 合格采样数据、采样率、加速度单位 | 输入不合格则阻止分析并说明原因 |
| 绑定某台设备的诊断报告 | 设备、测点与方向关联已经核对 | 可保存未关联分析，补齐前不发布针对该设备的诊断报告 |
| 转频及倍频标注 | 可靠的本次采集转速，且任务处于支持工况 | 仍展示普通频谱，不标注未经确认的转频 |
| 轴承理论特征频率与匹配 | 明确的目标轴承、适用的转速，以及经核对的几何参数或特征频率系数 | 该工具标记为不可执行；保留其他有效分析，列出缺失项 |
| 历史趋势或维修前后比较 | 可核对的设备、测点、方向和采集顺序，以及单位、采样/处理条件、转速与负载的可比性 | 明确区分不具可比性的展示与正式比较；信息不足时不宣称变好、恶化或维修有效 |
| 创建设备维修工单 | 设备已核对、有效且已复核的报告、明确动作与有权限人员确认 | 阻止创建；沿用后续工单需求的具体规则 |

- 门槛按工具和任务判断，不把“基础分析可用”等同于“足以判断具体轴承故障”。
- 未取得必要参数时，Agent 可请求补充或输出“存在异常但类型无法确定”，不能依据知识库中的相似案例补造参数。
- 未来若接入不依赖轴承几何参数的分类工具，应单独定义其适用范围、验证数据及拒答条件，不因此跳过全部适用性检查。

**US-E4 工况与参数来源**

作为复核人员，我希望知道每个关键参数的来源与确认情况，以便区分测量事实、台账参考和推断。

- 转速、负载和采集时间属于本次数据记录；测点与方向属于通道关联；轴承参数属于部件版本。分析任务保存采用的快照。
- 参数来源至少区分用户填写、可信文件/设备元数据、台账参考；来源不等于已核实。用户核对状态单独记录。
- 首版不从波形自动估计转速。用户手动提供的估计值标记为估计，不能静默升级成可靠实测值。
- 缺少负载时显示未知，不以 0 负载代替；不同表示方式（如 kW、额定比例、工艺描述）不得未经转换当作同一数值。
- 不同来源的关键参数冲突时，展示差异并由有权限人员选择和说明依据，记录所采用版本；冲突未解决则暂停依赖该参数的任务。
- 稳态/定速属于适用条件，应由采集记录和用户核对支持；仅填写一个转速值不能证明整个记录期间转速稳定。
- 修改会影响分析依据的参数后，旧结果继续保留并提示需重新分析；新结果生成后仍需按报告流程复核。

**本场景验收示例**

| 输入或操作 | 预期行为 |
| --- | --- |
| 合格 CSV、采样参数齐全，但没有设备关联 | 可做基础分析，标记待关联，不能写入某台设备的健康趋势 |
| 已关联设备，未提供本次采集转速 | 可看时域和普通频谱，转频工具不可执行并提示补充 |
| 有可靠转速，没有轴承几何参数或频率系数 | 可标注转频，不生成伪造的 BPFO/BPFI/BSF/FTF |
| 台账额定 1500 rpm，本次填写 1480 rpm | 分别保留额定与本次转速，不能将两者直接当作同一来源冲突 |
| 两个来源均声称本次实测转速，但数值不一致 | 提示来源冲突，暂停依赖该值的任务直至核对 |
| 同名设备存在两台 | 展示标识和测点供选择，不静默选第一台 |
| 复测方向或工况不一致 | 标记可比性问题，不自动计算维修效果结论 |
| 修改已出报告的数据单位或目标轴承 | 保留旧版本，提示重新分析及复核，不能沿用旧结论创建新工单 |

### 场景 A：现象诊断

**US-A1 多轮澄清**

作为点检员，我希望描述现象并选择已有数据，由系统按任务补充缺失信息，以便不必理解全部分析参数。

- 提取设备、测点、现象、时间与工况，展示抽取结果；数值必须绑定用户原话或已核对元数据，不凭空补齐。
- 单轮最多询问 2 个紧要问题；用户表示不知道时，记录未知并调整可执行任务，不反复询问同一问题。
- “夜班”等相对时间须由用户确认日期/时间范围；无采集时间的文件不自动匹配该描述。
- 参数齐全不重复追问；同名设备、多份数据或冲突参数必须明确选择。当前诊断任务绑定明确的数据 ID 与参数快照。
- 未上传数据时引导上传，不能声称已从现场设备拉取数据。可选授权范围内已有文件，不假设实时采集接口存在。
- 用户修改关键参数、切换数据或改变目标轴承后，说明先前证据是否失效，创建新的分析/诊断版本。
- 对话刷新可恢复；会话与任务状态分别展示，等待人工补充不计入自动执行时间。

验收：不完整描述触发针对性提问；补充后保存并推进；明确未知时降级；无数据时不生成诊断；切换文件不复用错误证据。

**US-A2 特征计算**

作为维修工程师，我希望对已校验的振动数据运行可复现的基础分析，查看时域特征与幅度谱，以便检查数据表现，并为后续轴承故障取证提供输入。

本小节定义基础工具；包络与轴承特征分析见 US-A4。基础分析完成不等于完成故障诊断。

**US-A2.1 明确指标与单位**

所有结果由确定性代码计算，基于换算到统一加速度单位后的分析信号。界面保留原输入单位及换算说明，不把加速度数值当作速度或位移指标。

| 指标 | 业务含义与约定 | 单位 |
| --- | --- | --- |
| 均值 | 分析段的算术均值，辅助观察 DC 偏置 | m/s² |
| 原始 RMS | 原始分析段平方均值的平方根，包含 DC | m/s² |
| AC RMS | 去除分析段均值后计算 RMS，和原始 RMS 分开标注 | m/s² |
| 绝对峰值 | 分析段采样值绝对值的最大值，不与峰峰值混用 | m/s² |
| 峰峰值 | 最大采样值减最小采样值 | m/s² |
| 峰值因子 | 绝对峰值 / 原始 RMS，与相应信号定义一致 | 无量纲 |
| Pearson 峭度 | 总体四阶中心矩 / 总体二阶中心矩的平方；不减 3、不做样本无偏修正 | 无量纲 |

- 换算 `g` 使用 9.80665 m/s²；结果记录原单位与换算系数。
- 不能仅依据某个指标升高就发布特定轴承故障、维修紧急程度或停机判断。
- 不使用“置信度”描述 RMS、频率等确定性计算值；诊断支持程度见 US-A3。

**US-A2.2 明确分析段与处理规则**

- 首个基础版本默认分析整个合格文件，不能暗中只用前 4096 点或前若干窗口。超资源限制时明确拒绝，不以局部结果冒充全量结果。
- 后续若支持手动选段，明确显示原文件中的起止采样索引、采样点数和相对时间，选段结果形成独立记录；本版本先不要求交互选段。
- 时域指标基于未加窗的分析段。幅度谱可按约定去均值和加窗，不将处理后的频谱输入回写成原始信号。
- 不自动删除冲击点、按固定幅值限幅、插值或重采样。以后新增处理必须可见、可配置、可追溯，并保留原始数据。
- 输入若为 N 点、采样率 fs，相对采样时刻为 0 至 (N−1)/fs；另外标注记录时长 N/fs，避免将最后采样时刻和记录时长混用。
- 记录所使用的数据版本、采样参数、处理步骤、算法版本和配置，使同输入及同版本可复现。

**US-A2.3 时域与频域展示**

| 展示项 | 必须呈现的内容 |
| --- | --- |
| 数据摘要 | 设备/测点关联或待关联状态、文件名、样本数、采样率、单位、记录时长 |
| 原始波形 | 横轴相对时间秒，纵轴加速度；明确是否仅对显示做抽样 |
| 指标卡片 | 数值、单位、清晰名称；不可计算时显示原因，不用 0 代替 |
| 单边幅度谱 | 横轴 Hz，纵轴加速度的峰值幅值；显示分析点数、去均值、窗类型和幅值标定约定 |
| 数据与任务提示 | 恒定信号、短记录限制、缺少工况、任务不可执行等提示，与诊断结论分开 |
| 追溯信息 | 分析 ID、原文件校验值、参数版本及处理配置，可从页面查看 |

- 幅度谱首版采用去均值、周期 Hann 窗及窗相干增益补偿；单边幅值正确处理 DC 与偶数点 Nyquist，不把 FFT 原始模值当作物理幅值。
- 标注频率 bin 间隔 fs/N；不要声称实际可分辨能力一定等于该间隔，也不通过补零声称获得更长记录的信息。
- 幅度谱、功率谱、功率谱密度和包络谱是不同结果，页面不得混用名称或单位。首版基础展示只要求单边峰值幅度谱。
- 主峰可以作为频谱观察值展示，但不能自动命名为某种故障；偏离 bin 的成分需按分析方法提示幅值和定位限制。
- 图表缩放、筛选频率范围、显示抽样只改变展示，不重新定义分析段或改变已计算指标。若后续加入选段重新分析操作，应生成新的分析记录。
- 波形预览若压缩显示，采用保留局部极值的方式并明确标记，以免普通抽点隐藏冲击；导出或复核可读取原始数据。

**US-A2.4 退化信号与任务状态**

- 零信号：RMS、峰值和峰峰值为 0；峰值因子和峭度显示不可计算及原因，不输出 NaN/Inf。
- 恒定非零信号：原始 RMS 及绝对峰值可计算、AC RMS 为 0；峭度不可计算；提示可能存在无有效动态信号，不直接判设备正常或传感器损坏。
- 输入不足按导入要求拒绝；满足基础计算长度但不足某个后续任务的时长要求时，仅限制该任务，不假装证据充分。
- 即使输入均为有限数值，计算中若发生溢出或数值异常，也应明确失败或标记对应指标不可用，不能写入假数值。
- 区分等待、运行、完成、部分可用、失败等用户可见状态；没有故障诊断时显示“基础分析已完成”，不显示“诊断正常”。具体状态字段在总体设计确定。
- 时间、资源或依赖故障应能定位；重试生成可追溯的新执行记录，不静默覆盖先前结果。

**US-A2.5 数值与交互验收**

数值容差须在实现前按每项指标约定，采用绝对误差与相对误差结合，不对接近零的值只要求相对误差。以下是已定义验证方法，尚非实测通过结果。

| 案例 | 预期 |
| --- | --- |
| 4096 点、4096 Hz 采样、128 Hz、峰值幅值 1 m/s² 的正弦 | 均值约 0，RMS 和 AC RMS 约 1/√2，绝对峰值 1，峰峰值 2，峰值因子约 √2，Pearson 峭度约 1.5；谱主峰 128 Hz、幅值约 1 |
| 上述信号叠加 2 m/s² 的 DC | 均值约 2，原始 RMS 约 √4.5，AC RMS 约 1/√2；去均值后的主峰位置和幅值保持一致 |
| 同一物理信号分别用 g 和 m/s² 表达 | 单位换算后的指标和幅度谱在容差内相同 |
| 相干采样的两个已知频率正弦叠加 | 对应峰值和幅值符合已知输入，不能只返回一个最大峰作为完整频谱 |
| 奇数/偶数点与偶数点 Nyquist 成分 | 频率轴正确，单边谱无错误翻倍或漏 bin |
| 零信号与恒定非零信号 | 正确区分可计算与不可计算项，有质量提示，无 NaN/Inf 响应 |
| 带单个大幅值采样的合格信号 | 不静默删除该点；峰值与原始记录相符，预览能保留冲击信息 |
| 仅调整图表频率范围或缩放 | 指标和分析 ID 不变，不截断原始数据 |
| 相同数据、参数、算法版本重复执行 | 数值在规定容差内一致，分别保留执行记录 |
| 已记录来源的 CWRU 数据导入 | 样本数、采样率、单位、处理配置与源文件对应；不据此直接宣布诊断正确 |

原“12k 数据 5 秒”和“全部相对误差 <1e-6”暂不作为硬验收。性能目标将在数据长度、硬件、并发和计算配置确定后细化，并记录耗时；不通过省略分析步骤来达标。

**US-A3 假设与取证**

作为维修工程师，我希望系统提出适用的故障假设、按需调用工具并检查矛盾，使结论受到实际证据约束。

- 先检查数据质量和设备适用范围，再提出内圈、外圈、滚动体等候选。候选数量由证据决定，不强制凑满 2—3 个。
- 每个候选记录必要条件、支持证据、反对证据、尚缺证据和下一项有效检查；不能把同一信号派生的多张图当作独立测量。
- 可调用工具限定为已注册、带参数约束的读分析工具：时域/频谱、包络、特征频率、谐波/边带检查、可比历史记录、知识检索。前置条件不满足时不能盲目调用。
- Agent 可根据当前结果选择下一工具；重复调用相同输入且无新增信息时复用可验证结果或停止，不无界循环。
- 模型输出经过结构校验、引用存在性校验、必要条件与证据规则校验后才成为诊断草稿。失败可有界重试，不能用任意文本直接发布报告。
- 支持程度首版使用“支持充分／支持有限／证据不足”，按版本化规则解释。模型自报百分比不作为可靠概率；分类器原始分数若展示须标明未校准及模型版本。
- 结果至少区分：支持具体故障假设、存在异常但类型无法确定、未发现支持目标故障的证据、无法分析/范围外。后两类均不等于完整健康证明。
- 持续存在关键证据冲突或范围不适用时，输出限制与补测建议，不用最高分强行定类。真实并发故障超出首发分离能力时标记无法可靠分离。
- 用户明确要求停止时可取消；中断/失败后的恢复策略见 US-A5。工程师可查看实际工具轨迹与简短判断依据，不要求展示模型内部思维过程。

验收：包含各故障候选、无目标故障证据、矛盾证据、缺参数和范围外案例；核对每条判断的源数据与工具结果；通过对照案例验证工具选择随证据变化。

**US-A4 包络谱与轴承特征频率**

- 包络流程至少记录去均值、带通频段、滤波器类型/阶数/相位策略、边界处理、Hilbert 包络、包络去均值及谱窗/幅值标定；保留输入与输出关系，不把处理结果当成原始数据。
- 允许采用经验证的配置预设或有权限工程师设置的频段。频段必须处于有效采样带宽内，不能仅因标称采样率较高就声称传感器有足够带宽。
- 数据长度不足滤波边界/周期观察要求，或频段非法时，工具明确不可执行。选择依据、有效分析长度、滤波截除的边界点须展示；不能无提示丢弃数据。
- BPFO/BPFI/BSF/FTF 由经核对几何参数及运动学假设，或带来源和适用条件的频率系数计算；明确假定哪个套圈旋转及参考转速。仅有轴承名称而无可靠映射时不能生成参数。
- 计算 FTF 可作为辅助观察，但不纳入首发保持架故障定类。滚动体相关的 BSF、2×BSF 等成分必须区分，不把它们混为同一频率。
- 匹配返回理论频率、搜索范围、实测局部峰、偏差、幅值、局部噪声参考、所检查谐波和边带；匹配频率容差由记录长度、转速不确定性和适用机制共同确定，并保存配置。
- 未找到显著峰时记录“未观察到对应支持”，不能直接排除所有故障；峰存在也不能单独证明故障。
- 近邻转频/谐波、多个故障频率重合、弱信号和滤波敏感结果应标出歧义，不能把最近 bin 自动记作显著证据。
- 校准标准：使用已知包络调制频率的合成信号、无调制对照、频率相近干扰、非法频段、边界短信号和公开记录验证；误差容差、显著性阈值在版本化算法配置中声明，并与测试集隔离。

**US-A5 有界执行、恢复与降级**

- 展示任务进度、等待信息和失败原因；首版支持刷新/重启后读取已提交状态。未完成的任务要么在安全检查后恢复，要么标记中断并提供显式重试，不能永远显示运行中。
- 首发默认每次自动执行最多 8 轮取证决策、20 次工具调用、每次外部调用最多 1 次自动重试、执行墙钟上限 120 秒；人工等待时挂起执行，恢复后执行预算累计。预算变更须有版本与审计。
- 单次模型调用默认最多 8k 输入输出 token；任务累计默认 32k，记录实际用量及模型原生上下文上限。超限返回已有有效分析及限制，不截断关键证据后伪装完整结果。
- 工具/模型调用配置超时；超过预算停止新增调用，保留已完成结果。用户取消后不再发布完整诊断或触发写操作；取消前完成的只读计算可留档。
- 模型不可用时仍可使用确定性分析；页面明确“未完成 Agent 诊断”。知识库不可用时，不依赖知识库的分析可继续并标记限制，不能伪造引用。
- 模型执行环境无任意 shell、文件系统、SQL、网络工具或动态代码执行权限；工单/配置写入不在自主工具白名单内。
- 验收覆盖超时、断网、工具抛错、格式错误、取消、重复请求、服务重启及预算耗尽。所有分支必须终止或进入明确可恢复状态。

### 场景 B：证据化报告

**US-B1 证据链**

作为维修工程师，我希望每条结论都绑定证据 ID，并能点开查看原始频谱或标准条款，以便判断结论是否可信。

- 每个数据证据保存源文件校验值、参数版本、片段、算法配置/版本、结果数值与单位、生成时间和工具执行 ID；知识证据保存文档与块版本及定位。
- 证据引用可点击查看对应图、参数或知识原文。支持、反对和缺失证据分别表达，来源关系可追溯。
- 对确定性诊断判断检查该假设的必要证据种类与有效性，不以“至少两个 ID”替代规则；重复/相关派生证据不能虚增支持度。
- 不存在、无权访问、版本不匹配或与当前输入无关的引用不能通过发布校验。标准文本或相似案例不能代替当前设备的测量证据。
- 证据记录一经引用即保留版本；撤回知识或修正数据后，历史报告保留原依据并显示失效/撤回提示。

验收：抽查每个发布判断到源文件的闭环，并注入伪造 ID、错文件、旧参数和撤回知识，验证被阻断或正确标记。

**US-B2 拒答**

作为设备主管，我希望证据不足时系统明确说「无法确定」并说明缺什么，以便不误导维修决策。

- 给定证据不足场景，系统应拒答而非给出故障结论
- 给定拒答，应列出缺失证据与建议补测项（延长采样、增加测点、补充工况）
- 无法分析与信息不足报告允许保存，但不能创建依据该诊断的维修工单；补测建议作为待办说明，不自动转成维修工单。
- 系统可以说明哪些基础分析已完成，不能把拒答整体写成设备正常；拒答原因应可分类统计。

验收：缺参数、数据质量失败、范围外、冲突未解均给出对应原因和可执行的补充项；可回答对照组避免过度拒答。

**US-B3 诊断报告**

作为维修工程师，我希望得到结构化报告：现象、数据、特征、证据链、结论、建议、紧急程度。

- 报告固定七块：现象与目标、数据及工况、分析方法与特征、支持/反对证据、判断与限制、建议及人工处理优先级、版本与复核信息。某块无内容须说明原因。
- 建议区分检查/补测、复检和可能维修措施；没有依据时不强填更换备件、拆机或具体时限。维修动作、备件型号和执行时限由有权限人员复核确定。
- 业务处理优先级为低、普通、高、紧急；模型只能提出有依据的草稿建议，工程师确认并可修改，高/紧急工单须主管审批。优先级不等于机器振动标准分区。
- 首发不提供通用 ISO 烈度自动分级；显示“未启用标准分级”，不得把加速度 RMS 直接套用速度分区。以后启用需明确适用设备、测量量、频带、单位、标准版本、合法来源及验证。
- 状态包括草稿、待复核、已复核、已替代/撤回。原始模型文本不能直接成为已复核报告；改写关键判断、参数、证据和动作需生成新版本。
- 人工复核可接受、修改或退回，记录人员、时间和理由；工程师自行新增且无系统证据的判断须标明人工补充及依据，不冒充系统诊断。
- 支持查看历史版本及差异，导出包含图表和版本的离线 HTML 与结构化 JSON。未复核导出显著标为草稿；HTML 不执行上传内容脚本、不访问远程资源。
- 首版不要求 PDF/DOCX 导出（P1）。报告分享通过授权访问或受控导出，不创建默认公开链接。

验收：七区块齐全、所有引用可解析；复核前后状态和版本正确；修改使旧确认失效；导出可独立阅读且不混淆草稿/已复核。

### 场景 C：工单闭环

**US-C1 人工确认**

作为维修工程师，我希望确认或修改结论后才生成工单，以便模型不能直接触发写操作。

- 给定未确认状态，工单接口应拒绝创建
- 确认绑定报告 ID/版本、设备、动作、优先级、审批人和有效期；服务端检查报告仍有效且具备权限，不能信任客户端的 confirmed 字段。
- 普通/低优先级由有权限工程师确认；高/紧急先由工程师确认再由设备主管批准。相同账号仅在被明确授予相应角色时可执行对应步骤，审批轨迹分别保留。
- 报告被替代、动作修改、授权撤销或确认过期时拒绝旧确认，重新复核；过期策略与具体凭据实现由总体设计确定。
- 同一确认与幂等键在并发/超时重试下原子地返回同一张工单；同一键不同动作返回冲突，不允许生成两张。需另外创建工单时显式发起新请求并说明原因。
- 会话恢复、模型重试或浏览器刷新不能自动消耗确认或创建工单。工单创建成功但响应丢失可查询到原结果。

验收：未授权、未复核、过期、旧版本和待主管审批均不能创建；并发重复提交只生成一张。

**US-C4 工单状态与执行记录**

- 首发是内部维护记录，不对接 MES/CMMS、不自动派工。状态为待审批、待执行、执行中、待复测、已关闭、已取消；转换需有权限人员操作和服务端校验。
- 工单保留关联报告版本、设备、确认动作、优先级、建议与最终期限、执行人员及实际执行记录；实际执行人员由授权人员手动指定，未执行前不记录完成事实。
- 取消、改期、动作变更和关闭均记录原因；关键动作变更需重新审批。不能通过改工单动作绕过报告确认。
- 工程师执行完成后进入待复测；无法复测时允许主管以“未验证”状态说明原因并关闭，不能自动记为维修有效。

验收：非法状态跳转被拒绝；关闭/取消历史完整；无复测关闭仍明确保留未验证标记。

**US-C2 审计**

作为设备主管，我希望每次诊断可追溯：谁发起、用了哪些数据与工具、模型版本、确认人。

- 审计包含操作者及角色、对象 ID/版本、动作、前后状态、原因、时间、请求/任务关联 ID；诊断还关联数据、参数、工具、模型供应商/名称、可获知的版本、prompt/知识配置版本。
- 用户与应用接口只能追加，不能修改或删除审计；更正通过新事件关联旧事件。该要求不等于宣称具有抵抗数据库管理员篡改的绝对能力。
- 授权人员按设备、报告、会话或工单可从一个详情入口还原完整链路，支持分页导出；不要求所有明细必须由一条数据库查询完成。
- 日志不包含密钥、密码或完整认证凭据；模型供应商不提供精确版本时如实标为未知，不能用别名伪装固定权重。

验收：从一张工单找到对应报告、数据与工具调用；更正事件可追溯；普通账号不能修改审计和读取未授权记录。

**US-C3 复测闭环**

作为维修工程师，我希望维修后回填复测数据，对比维修前后特征，以便验证诊断是否有效。

- 执行完成后提示上传或关联独立复测记录，保留采集时间和来源；不将原始数据复制成“复测”并自动判成功。
- 先检查场景 E 的可比性，满足条件后输出 RMS、峭度及可用特征频率证据的前后值、变化量与配置；原值接近零时不输出失真的百分比。
- 条件不完全一致时可并排展示并标注限制，不自动得出维修有效；无真实维修记录不声称信号变化由维修导致。
- 复测仍异常可创建关联的新诊断任务/会话分支，引用旧记录而不覆盖，必要时由人员创建新的工单。

验收：可比数据输出正确对比；不同比较条件给出限制；新诊断保留完整历史与责任人。

### 场景 F：知识库与 RAG

**US-F1 知识导入与版本**

- 工程师上传 UTF-8 MD/TXT，每文件最多 5 MiB；PDF、图片 OCR 与其他格式为 P1。知识入口与信号入口分别校验。
- 必填标题、来源说明、适用设备/部件、内容版本或发布日期及使用授权说明；可补充网址、作者。未知值如实标记，不伪造标准或厂家出处。
- 知识状态为草稿、处理中、待审核、已发布、失败、已撤回。有知识审核权限的工程师发布后才能进入正式检索；审核权限由管理员显式授予。
- 文档修改生成新版本；块索引保留文档版本、标题层级、段落/行范围和校验值。重新索引失败不破坏原已发布版本。
- 重复内容提示复用或显式创建新版本，不重复导入造成检索加权。MD 外链和内嵌脚本不执行，不自动下载关联文件。
- 未具备使用权的标准全文、手册不随产品预置；可存合法摘要与来源定位。开发测试语料与正式知识库分别标记。

验收：MD/TXT 能解析发布；重复上传有提示；失败索引有状态；未审核与撤回版本不进入新任务检索；历史引用仍可追溯。

**US-F2 检索与引用**

- 以当前假设、设备/轴承适用条件及分析发现构建检索请求，按发布状态、访问权限和适用范围过滤，再返回相关块；不能跨权限先检索后只隐藏展示。
- 每次记录检索词、过滤条件、索引/嵌入模型版本、返回块、排序分数；分数是检索相关性，不是诊断概率。
- 首发每次默认最多 5 块，可配置并受上下文预算限制；关键上下文不足时说明限制，不截断后丢失来源。
- 生成的知识性建议引用具体块；无可靠命中时明确“未找到适用资料”，不能编造手册章节或标准条款。
- 诊断关联本次实际使用的知识版本，发布新文档不静默改变历史报告；用户发起重新诊断才采用新知识。

验收：用预标注问题检查召回与引用定位；无关文档、错误设备、撤回和无权文档不提供错误支持；引用可回到对应版本原文。

**US-F3 非可信内容与冲突**

- 用户描述、文件名、MD 正文和检索片段均是待分析内容，不能覆盖系统规则、扩大工具权限、读取密钥或绕过审批。
- 文档含“忽略规则”“调用工单工具”等文本时只作内容处理；工具权限和发布校验在模型外执行。
- 知识相互冲突、过期或与当前数据不一致时展示冲突和来源，降低适用性或请求复核，不隐藏反对资料。
- 验收包含提示注入、恶意 Markdown/HTML、伪造来源、跨权限检索和冲突知识；不得产生越权读取、脚本执行或写操作。

### 场景 G：账号、权限与系统设置

**US-G1 身份与角色**

- 单组织部署，不提供公开注册。管理员创建/停用账号、授予角色和设备范围；初始管理员通过部署流程建立，首次使用更改初始化凭据，不内置通用默认密码。
- 登录会话有过期与注销机制；密码安全散列存储、失败登录限流，敏感配置操作重新验证身份。停用/撤权后新的请求与后台任务读取权限必须生效。
- 下载、导出、任务查询、证据链接及知识原文都执行服务端权限校验，用户不能凭猜测 ID 访问。
- 已启动的任务若因撤权不能继续获取资源，应安全停止或限制结果访问；不得按旧权限继续导出或批准工单。

| 操作 | 点检员 | 维修工程师 | 设备主管 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 授权范围内导入、补信息、查看基础分析 | 可 | 可 | 只读查看，额外写权限另授 | 不默认拥有业务读取权 |
| 发起诊断、查看授权诊断记录 | 可发起/查看，不能复核 | 可 | 可查看 | 不默认拥有 |
| 维护台账、核对关联与轴承参数 | 不可 | 可 | 可核对，写权限另授 | 不默认拥有 |
| 复核报告、确认低/普通工单 | 不可 | 可 | 需兼具工程师角色 | 不默认拥有 |
| 批准高/紧急工单、未验证关闭 | 不可 | 不可 | 可 | 不默认拥有 |
| 上传知识 / 发布知识 | 不可 | 可上传；发布另授审核权限 | 需相应授权 | 仅管理权限，不默认发布 |
| 管理账号、模型配置、备份 | 不可 | 不可 | 不可 | 可；备份属敏感操作并审计 |
| 查看审计 | 仅本人操作结果 | 授权业务对象 | 授权业务对象 | 系统运维审计，业务内容按授权 |

未关联文件仅上传者和明确授权的工程师可访问；关联设备后也不得因此自动扩大到全体账号。访问范围与具体授权策略在总体设计中落实，不提供匿名业务接口。

验收：各角色正/反向权限案例、水平越权、撤权、会话过期与登出；仅前端限制视为未通过。

**US-G2 配置与密钥**

- 可配置模型供应商、模型名、地址、超时、预算和知识索引参数；API Key 由部署密钥机制保护，界面仅显示已配置状态/掩码，不回传明文。
- 模型适配接口支持外部 API 与本地服务，试用交付至少验证一个本地和一个获准的外部模式；具体模型在总体设计选定。
- 默认禁用外部模型调用。管理员明确启用后，界面显示数据外发边界；只发送必要特征摘要和授权知识块，不默认上传完整原始波形。模型地址通过受控配置，防止任意地址探测。
- 改配置产生版本、操作者与时间，已运行任务保留原快照。测试连通性不使用真实业务文件，不将测试响应记为生产诊断。
- 不提供模型时允许基础分析，模拟响应仅存在于明确标识的开发/演示配置，正式试用验收不接受 mock 诊断结果。

验收：未启用外发时无外部模型请求；密钥不进入导出/日志；切换配置不改变旧报告；模型不可用正确降级。

### 场景 H：工作台、检索与记录管理

**US-H1 页面与导航**

- 必备页面：登录、设备/测点台账、数据导入与列表、分析/诊断工作台、报告列表/详情、工单与复测、知识库、管理设置与审计查询。
- 主工作台围绕同一任务展示输入摘要、质量提示、图表、候选假设、工具进度、证据和待复核报告；关键限制不藏在日志中。
- 列表支持分页、按设备/状态/时间筛选和明确的空/加载/错误状态；筛选时间注明采集时间或上传时间，不能混用。
- 页面刷新、断线重连后读取服务端实际状态，不依赖浏览器缓存充当完成结果；重复点击分析或确认防重复。
- 首发提供桌面浏览器中文界面，键盘可操作主要控件；图表必须有文本摘要与单位，不能仅凭颜色区分支持/反对或风险。
- 设备详情只展示有来源的记录和可比较趋势，不产生实时在线率、预测寿命等假数据。实时大屏、地图和 3D 展示不属于 P0。

验收：新用户按操作说明完成导入到复核；刷新保留状态；失败可重试；无记录时不填充未经标记的演示数据。

**US-H2 数据生命周期与导出**

- 业务数据、测试数据、仿真案例按来源类别显式标记，列表/导出可筛选。上传物理内容去重不得泄露其他用户是否拥有同一文件。
- 原始文件、分析、证据、报告、工单和审计通过稳定 ID 关联。文件损坏或缺失时校验失败并阻止继续发布相关判断，不展示缓存结果冒充可验证证据。
- 首发默认不自动物理删除任何已被报告/工单引用的文件和版本；管理员可归档并制定经确认的保留策略。磁盘不足时拒绝新上传并告警，不自动删除历史数据。
- 未被引用的数据可由有权限人员申请删除，说明影响并记录审计；已引用记录只能按归档/受控清理流程处理。清理不留下看似有效但无法解析的证据引用。
- 账号停用不删除其历史操作归属；知识撤回保留历史依据和撤回标记。备份副本的保留与清理范围向管理员说明。
- 导出需权限检查与审计；原始 CSV、分析 JSON、报告 HTML/JSON 为 P0。导出不能包含密钥、其他设备数据或隐藏的无权知识。

验收：归档、删除被拒、磁盘不足、文件校验失败和越权导出案例符合预期，历史报告不静默失真。

### 场景 I：部署、运行与恢复

**US-I1 安装与升级**

- 提供 Docker Compose 单机部署、示例配置、初始化步骤、数据卷说明、健康检查和版本清单；支持持久化数据与模型服务分离配置。
- 首次部署可联网准备依赖/镜像；如目标内网隔离，提供离线导入所需镜像、模型和依赖清单，本地模式运行不依赖外部 CDN、字体或云数据库。
- 共享试用环境启用认证和 HTTPS/受控反向代理；数据库与管理端口不默认暴露公网。开发本机模式须明确标识，不能当作共享试用配置。
- 升级前备份，提供数据迁移与兼容性说明、失败回退步骤；不承诺任意数据库版本降级可直接运行旧代码，必要时恢复升级前备份。
- 安装说明列出已验证的宿主环境、硬件、磁盘和端口，未验证平台不声称支持。

验收：干净环境按说明安装成功，重建容器不丢记录；断外网本地模式完成业务链路；执行一次升级失败回退演练。

**US-I2 可观测与恢复**

- 提供存活/就绪状态，区分数据库、文件存储、分析工具、模型与知识索引依赖；模型不可用不等于基础分析全部不可用。
- 记录请求/任务 ID、阶段耗时、错误码、队列长度、工具成功率、模型用量与可获知费用；费用未知时不伪造金额。
- 配置日志轮转、磁盘容量提示和任务超时；本地查看运行状态即可满足首发要求，不强制外部告警集成。
- 首发提供每日备份调度和人工备份入口/命令，覆盖元数据、原文件、报告、审计及必要配置；凭据恢复通过独立受控步骤，不明文装入普通导出。
- 备份期间使用一致性策略，恢复后核对文件校验值、对象关系和工单幂等记录；知识索引可重建，但来源和版本必须保全。
- 默认恢复目标 RPO ≤24 小时、RTO ≤4 小时，为试用容量下的设计目标，交付前通过独立目录/实例恢复演练实测。备份放置于与活动数据不同的存储位置；同机副本不宣称防主机整体损毁。
- 断电/进程中止后，已确认工单不能重复创建，未完成任务不得显示成功，前端可读到明确状态。

验收：故障注入、日志脱敏、服务重启和独立恢复演练；备份只有文件生成而无恢复验证视为未通过。

## 5. 非功能需求与资源边界

### 5.1 首发容量及性能基线

以下是用于实现和验收的暂定基线，不能在缺少实测时写成产品已具备的性能。若目标不能达到，应在发布前调整实现或修订范围并记录原因。

| 项目 | 首发目标及测量条件 |
| --- | --- |
| 参考主机 | 8 个逻辑 CPU、16 GiB 内存、SSD、64 位 Linux Docker 主机；精确 CPU/OS/镜像版本随测试报告保存 |
| 模型资源 | 模型进程/推理设备另列；16 GiB 应用主机不保证可容纳任意本地大模型。外部模型包含实际网络与供应商耗时 |
| 活跃用户 | 10 个已登录操作会话；首发最多 2 个并发计算/诊断任务，其余有界排队，队列默认最多 20 个，满时明确拒绝并提示重试 |
| 数据容量 | 验收样本为 100 台测试资产、1000 份数据、1000 次诊断；每 CSV 同时满足 32 MiB 与 1000000 点上限 |
| 基础分析耗时 | 12000 Hz、120000 点单通道，单任务从受理到结果可读 P95 ≤5 秒；上传时间单独记录 |
| Agent 自动诊断耗时 | 参数齐全、上述典型信号、指定模型配置，含排队/读取/工具/模型 P95 <30 秒为目标；统计真实重试，超时不能剔除，成功率另报 |
| 交互 | 分页列表/任务状态等普通接口，在参考数据量和 10 会话下 P95 ≤2 秒，不含大文件下载和模型执行 |
| 压测 | 至少 100 次典型基础分析；Agent 至少 100 次自动诊断并另测并发排队。样本、冷/热缓存、模型配置和失败计数必须报告 |
| 稳定性 | 连续 24 小时数据回放与业务查询测试：无非预期进程退出、无已确认数据丢失、无重复工单；持续资源增长须分析并设上限 |

- 上传、解析、分析、检索和导出都有内存/大小/超时限制；不能一次性加载无限数据或创建无限线程。
- 排队计时计入端到端时延。超时任务计为未在目标内完成，不仅对成功的快任务计算 P95；任务完成率和失败/取消率分别列出。
- 基础分析不依赖 GPU；本地模型资源按实测配置声明。单机首发不提供高可用承诺，故障恢复依赖备份与操作方案。

### 5.2 正确性、隔离与接口行为

- 时间采用带时区语义存储，页面按配置时区显示；上传时间、采集时间、执行时间和人工确认时间分别保存。
- 计算统一单位、数值定义与版本。浮点无效值不可进入合法成功结果；数值容差在工具测试规范中逐项给出。
- 所有业务 ID、状态转移、访问范围和输入限制由后端验证。使用参数化持久化操作、限制上传路径、避免危险反序列化与任意对象加载。
- 对认证、上传、诊断、知识索引和导出限流；失败输入不进入模型调用。服务端不把内部异常、路径、认证头返回用户。
- 原始数据不可变，业务修正保留版本。用户操作并发冲突使用版本校验返回冲突，不按最后写入静默覆盖已确认结果。
- 断线、重复请求和重试不会产生额外副作用；具体 API、状态码、事务及幂等实现由总体设计定义，并覆盖各故事的验收。
- 数据库/模型/框架具体版本在总体设计和依赖清单确定，不因需求文档使用示例而默认采用未经验证组件。

### 5.3 可维护与供应链

- 分析工具、Agent、知识检索、模型适配与业务写入具有清晰边界；可独立测试工具，不依赖真实模型完成所有测试。
- 开发测试 mock 与真实诊断在配置、结果和验收上区分；试用交付必须有真实模型调用的端到端记录。
- 保留依赖锁定、来源/许可证清单；修复影响文件处理、权限、外发及框架运行的高风险已知问题，无法修复的须有明确限制和发布处置记录。
- 提供开发启动、测试、构建、部署、备份恢复、升级回退和排障说明。全新环境按文档复现，而非依赖开发机隐含配置。
- 日志及测试报告使用脱敏数据；备份/业务导出作为敏感资料管理，不能默认放公开下载目录。

## 6. 评测需求

### 6.1 数据与划分

- 建立数据清单：来源 URL/说明、授权条件、文件校验值、标签来源、采集参数、通道、设备/轴承身份、工况和转换脚本版本。
- CWRU 为首发四类主线；按原始记录或更高层关联实验组划分，再生成窗口。存在同一试验/相邻采集的关联记录时归同组，避免把相关片段分入开发与测试两端。
- 开发/验证/测试清单固定版本；阈值、prompt、检索内容和规则调整只能利用开发/验证集，不读取测试金标调参。数据量不足以实现某种隔离时明确说明，不包装成跨设备泛化。
- 模型和 Agent 输入中去除标签编码文件名、故障目录、测试金标及会泄露目标的元数据；数据来源 ID 仅用于追溯，不作为类别提示。
- 公共数据、仿真异常、工程功能案例和外部数据分别报告。Paderborn 为外部检验候选，至少在交付前完成一个实际可用的独立外部来源验证；标签不兼容时明确映射或只测可比较任务，不塞入主线准确率分母。
- 仿真记录生成方法、随机种子、噪声/缺失/削顶/漂移等变化及目的，不声称代表完整现场分布；仿真数据不能用于证明现场维修效果。

### 6.2 指标口径与目标

| 指标 | 分母与判定 | 首发开发目标 |
| --- | --- | --- |
| 主线准确率 | 已固定测试集全部符合评测任务条件的记录；拒答按未判对，窗口先按固定策略聚合到记录，不能把同记录窗口当独立样本扩充分母 | ≥0.85 |
| 正常误报率 | 正常测试记录中被判为目标故障的比例；同时报告正常拒答率 | ≤8% |
| 回答覆盖率/已回答准确率 | 分别为给出可判类别的记录/全部，以及回答正确/已回答；与总体准确率同时报告 | 必报，不单独以高分宣称通过 |
| 应拒答识别率 | 预标注应拒答案例中正确拒答的比例，原因与案例相符 | ≥0.90 |
| 错误拒答率 | 预标注可回答案例中错误拒答的比例 | ≤10% |
| 证据引用完整率 | 发布诊断判断中引用可解析且版本/对象相符的比例；无发布判断时不记为100% | 100% |
| 无必要有效证据却发布确定性判断 | 针对标注缺必要证据/冲突未解案例逐项检查 | 验收集中为0 |
| RAG Recall@5 | 有已发布适用知识金标的问题中，前5块至少命中一块金标的比例 | ≥0.80 |
| RAG 引用正确性 | 抽查生成引用是否真实、定位正确、支持对应知识陈述 | 所有发布引用可解析；语义支持性逐条评审 |
| Agent任务完成率 | 预定义任务中得到预期成功/拒答/降级终态的比例，按案例预期判定而非仅看返回200 | ≥0.90 |
| 权限/确认/幂等 | 强制安全与写入约束案例 | 全部通过，无越权与重复工单 |

- 每类诊断结果报告混淆矩阵、precision/recall/F1、样本数；正常标签映射为评测上的正常，不将其扩大成产品健康保证。
- 应拒答/可回答集合各至少 30 个独立案例，RAG 至少 30 个标注问题；主线类别数量按实际数据清单列明，不合成重复窗口伪造独立样本量。
- 金标来源、规则依据与人工标注者身份/资质如实记录。没有工程师评审时标为开发标注，不宣称专业人员已确认维修建议。
- 对比至少包含规则基线、基于相同可用摘要的单次模型判断、工具取证 Agent；记录模型、prompt、工具和成本，不能通过额外泄露标签获得优势。
- 失败案例保留输入、期望、实际结果、原因与修复版本；修复后以回归集复测，正式测试集失去隔离时重建评测版本并声明。
- 公开数据指标仅支持相应范围，工厂适用性由第 7 节现场接入核对与人工复核决定。

## 7. 试用准入与端到端验收

需求到验收案例必须有可追溯映射。总体设计/版本计划须为所有 P0 故事及第 5—7 节要求分配具体用例 ID；下表是最少跨模块验收场景，不替代各故事条目。

| 用例 | 操作与预期 | 覆盖 |
| --- | --- | --- |
| AT-01 标准分析 | 新用户导入合格 CSV、确认采样参数、查看校准图表和追溯信息 | D、E、A2、H |
| AT-02 无设备/参数缺失 | 基础分析可用，专门诊断受限，无默认转速、无虚构特征频率 | E、A1、A4、B2 |
| AT-03 工具取证 | 合法诊断执行实际工具，候选有支持/反对证据；拒答案例给补测项 | A3—A5、B1—B2 |
| AT-04 知识闭环 | MD 导入、审核、发布、检索及引用定位；更新/撤回不改变历史 | F、B1 |
| AT-05 复核工单 | 报告复核、普通工单确认、高优先级审批、执行与复测，全程版本可追 | B3、C1—C4 |
| AT-06 重复/旧确认 | 并发提交、响应丢失、旧报告、过期确认和越权操作均不重复或越权写入 | C1、G、5.2 |
| AT-07 故障恢复 | 模型断网、格式错误、工具超时、取消及服务重启进入正确终态 | A5、I2 |
| AT-08 数据修正 | 改单位/转速/测点后保留旧结果，新任务采用新快照，旧确认不被复用 | D3、E4、B3、C1 |
| AT-09 安全输入 | 非法 CSV、路径片段、恶意 MD、提示注入、越权 ID/检索不产生危险动作 | D2、F3、G、5.2 |
| AT-10 部署与恢复 | 全新部署、离线本地模式、持久化、备份独立恢复与失败回退均通过 | I、5.3 |
| AT-11 容量和性能 | 执行性能/并发/24小时回放，保存配置、完整失败计数和资源曲线 | 5.1、A5 |
| AT-12 效果评测 | 固定划分上的四分类、拒答、RAG及Agent评测，失败记录可复现 | 第6节 |

试用交付包必须包含：可部署版本、配置模板、兼容范围、测试数据/来源说明、操作手册、验收报告、已知限制、备份恢复与回退步骤、故障反馈模板。

接入具体工厂前核对：设备/轴承与转速范围、稳态条件、传感器类型/安装方向/单位/带宽与校准情况、文件格式、数据权限、部署网络和人工复核责任人。条件不符则只开放经验证的分析功能，不能以公开数据成绩替代现场核对。

现场首轮以人工复核的影子/辅助分析方式使用，不接停机/产线控制。设备范围扩大、算法/模型/知识关键版本变化后重新验证适用性；软件验收通过不自动等于现场效果通过。

## 8. 设计假设与待实测项

本节是需要总体设计和验证落实的事项，不是尚未书写的功能需求。

| 项目 | 当前设计选择 | 后续落实方式 |
| --- | --- | --- |
| 现场输入 | 单通道、均匀采样加速度 CSV，采样参数可核对 | 适用性清单与导入校验；不符合者先转换/补参 |
| 稳态定速范围 | 不预设任意转速均可诊断 | 算法配置中声明支持范围，并结合传感器和记录长度验证 |
| 工具阈值/频率容差 | 版本化规则，不由模型自由决定 | 仅在开发/验证集设定，测试前锁定 |
| 数据库、队列、前端与模型 | 尚未选定具体实现与版本 | 总体设计给出依据及替代方案，需求不预设必须堆叠组件 |

| 性能/恢复目标 | 第5节为首发验收基线 | 压测与独立恢复演练，不达标则修订并留痕 |
| 诊断与建议可靠性 | 公开数据及开发标注先验证 | 评测报告注明边界，现场由适格人员复核 |
