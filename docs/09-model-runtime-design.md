# 09 正式模型调用与受限决策设计

> 版本：v0.3；日期：2026-10-31。T04a为网关预检，T04b1/T04b2已接可选方法及数值模型图；效果评测留T05。
> 上游：[07 Agent设计](07-m3-agent-design.md)、[08 知识设计](08-knowledge-design.md)。

## 1. 分步范围

T04a建立独立于M0原型的有界模型网关、任务级配置绑定、模型轮账本及决策/原文摘录验证；使用真实DeepSeek和本地Qwen进行开发兼容检查。网关返回经过校验的建议，不执行建议、不发布草稿、不把少量接口样本当模型效果准入。现有规则图仍是默认执行方式。

T04b再增加新图版本，接候选生成、模型选择、真实授权执行与未发布草稿；旧图/旧任务不自动升级。T05用固定任务与留出样本对照规则、单次模型、Agent，区分完成、拒答、降级、错误、成本和适用条件。

## 2. 外部与本地配置

[formal-models.json](../backend/config/formal-models.json)列出两个显式配置：deepseek使用DeepSeek API的deepseek-flash；ollama使用回环服务中的qwen3.5:2b及已观察到的固定manifest digest。最大输出512 token，温度0，关闭思考；本地请求CPU/4线程、8192上下文及固定seed。它们是开发配置，不是工业效果已合格的结论。

VIBRADIAG_FORMAL_LLM_PROVIDER只决定尚无绑定任务的默认配置；每个任务首次模型轮将配置及hash写入不可变agent_model_bindings，配置同时包含系统提示、采样参数、上下文边界等策略hash，后续沿用该绑定。显式要求换供应商返回冲突，不在任务中途改变身份。切换配置供后续新任务使用；不在云端失败时偷偷切本地，也不自动拉模型。原型的VIBRADIAG_LLM_PROVIDER与此分开。

DeepSeek还须全局外发开关和私有API key；每次请求前复核开关。端点固定官方HTTPS，关闭代理环境和重定向，不允许用户提供URL/密钥/任意模型名。本地端点固定http://127.0.0.1:11434，调用前后检查tag digest。云端无法自行证明实际权重版本，记录请求/实际返回模型身份；本地manifest与运行版本也不等于远程权重或硬件执行证明。

## 3. 最小外发上下文

当前仅支持已确认范围的方法任务；查询来自当前任务短查询，不含采集根。decision上下文只有问题、允许candidate_id/动作名和结束范围；候选的组织/任务/根/调用键等完整结构留在服务端做策略校验，不发给模型。

extractive_draft必须先有本任务、本调用已完成的授权检索。上下文最多5个真实source_id及每块前400字符正文，标为不可信资料；不发CSV、波形、文件路径、会话、数据库连接、模型密钥、角色快照或任意工具载荷。用户问题和资料中的自然语言不获得指令权限。来源声明不等于独立认证。

服务端固定系统约束和JSON schema。云端JSON模式只保证格式方向，仍须本地Pydantic与策略检查；本地schema格式也不能代替权限/引用验证。总用户提示≤24000字节，本地系统与用户提示合计≤6000字节，为8192上下文及输出留保守空间；超出拒绝而不静默截断原查询。本地服务仍须在已验证版本/模板下运行。

## 4. 决策与摘录

decision只能选择服务器登记candidate_id，或以insufficient_evidence结束；不能返回任意函数/参数、URL、SQL、配置、诊断或维修动作。现阶段只有方法检索候选，不支持模型自行创建澄清问题或声明已有分析结论。

extractive_draft仅接受最多3条source_id＋原文quote。UUID必须来自本轮提供的当前来源，quote必须是提供片段中非空、≤400字符的逐字子串；拒绝改写、未授权来源、重复来源和伪造内容。无依据可以明确返回insufficient_evidence。此设计只控制摘录真实性，不证明相关性或工程语义；不生成开放式诊断回答，不宣称确定性故障、健康、严重度、停机或维修有效。

输出前后重查任务/租约、来源/范围和输入快照；摘录结果提交时锁定来源发布与索引头，重新生成上下文指纹并验证。旧来源、撤权、取消或过期预算拒绝迟到结果。T04b必须再次把实际执行候选及最终引用接入相同边界。

## 5. 轮次账本与恢复

0018新增agent_model_bindings和agent_model_rounds两表，当前44张业务表、4张检查点表。模型轮在请求前预留既有8轮模型预算；每轮保存任务绑定、phase、logical_key、配置/上下文/schema/prompt指纹和必要受控上下文。状态为running/completed/failed/interrupted，结束后不可改写或删除。

每个逻辑轮在T04a只发起一次真实请求，无自动格式修复、网络重试或供应商回退。已完成且当前上下文仍一致时重放返回同一校验输出，不二次调用；失败/未知轮不伪装成成功、免费重试或退款。正式图的有限显式恢复策略由T04b补齐。响应未知可能已产生供应商费用；未提交回执不能当作未执行。

记录请求/返回模型、可获知的digest/运行版本、输入/输出token、耗时、原始响应hash、校验后结构化输出或固定错误码；不保存失败的原始正文，不回显供应商报错/认证头。任务查询只展示轮次状态与脱敏身份/用量，不公开上下文或原始响应。确认调用与执行未知分别标记，model_called不再恒为false。

## 6. 资源、权限与验证边界

单进程正式网关一个名额，单轮等待≤60秒并取任务剩余时间小值；流式读取有2MiB上限，响应内容≤8192字节，拒绝空白、截断、工具调用或错误角色。HTTP请求本身不开放供应商工具/联网搜索；未授权、余额、限流和网络故障用固定错误码记录。取消保护持久结果，但不保证供应商服务端推理已停止。

调用仅为内部服务，不新增公开试验/任意prompt接口。模型预检使用专用测试库、单进程租约和自编方法资料；分别记录真实云端与本地的兼容性、清晰样例完成和失败，不把schema通过、合法拒答与任务成功混为一谈。当前只有英文开发兼容样例，不作中英文工业能力排名。

见[T04a验证记录](acceptance/M3-T04a-verification.md)。依据：[DeepSeek JSON模式](https://api-docs.deepseek.com/guides/json_mode/)、[DeepSeek模型说明](https://api-docs.deepseek.com/quick_start/pricing/)、[Ollama Chat接口](https://docs.ollama.com/api/chat)。模型别名、服务和价格可能变化，记录本次实际返回身份与用量，不声称云端权重永久固定。

## 7. T04b1 方法模型图实施

VIBRADIAG_METHOD_EXECUTOR默认rules，显式model才对新方法任务采用model-method-v1。配置在受理时进入不可变输入快照，而不是等首次请求才读取默认值；数值任务仍用规则图，旧方法任务不受新开关影响。公开请求不能覆盖这些配置。

模型决策经当前候选验证后才允许服务器执行授权检索，模型选择finish则不调用工具；有有效检索才生成逐字摘录。最终成稿从当前账本重建并验证，模型决定和原文不能成为任意参数或写动作。失败/未知模型轮不自动重试，摘录不可用保留固定资料提示；输入/模型配置或来源变更需要按明确流程新建任务。

提示策略v2将决策前无来源的正常状态与摘录后无支持的拒答分开；这为T04a失败提供迭代路径，并不证明单例能解释全部本地模型表现。两模型的本次流程结果见[T04b1记录](acceptance/M3-T04b1-verification.md)。下一步T04b2数值动作候选/条件检查，T05再做完整效果评测。

## 8. T04b2 数值模型策略与图

VIBRADIAG_NUMERIC_EXECUTOR=model启用独立数值图，默认rules。受理固定配置使用formal-numeric-json-v1策略hash；方法v2的hash及历史配置不改写，网关拒绝跨阶段混用。数值上下文只含受限问题、实际回执状态/缺项及候选ID，不发送原始波形。

模型至多6轮选择5次真实工具，或明确结束；多候选可选择包络/理想频率顺序。匹配候选依赖真实父结果及不确定量检查，不能由模型绕过。最终草稿为服务器固定文案与实际引用，未开放数值诊断生成功能。见[T04b2验证](acceptance/M3-T04b2-verification.md)；T05再开展规则/单次模型/Agent对照，本地既有拒答不改写。
