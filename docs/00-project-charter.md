## 1. 一句话定位

面向工厂设备运维的滚动轴承离线振动诊断助手：工程师导入振动数据并描述现象，系统检查数据与适用条件，由代码计算特征，Agent 组织故障假设与工具取证，输出可追溯、可人工复核的诊断报告，人工确认后形成内部工单与复测记录。

交付目标：完成一个能够在工厂内网部署、接入符合约定格式的现场文件、由人员复核使用的受控试用版本。离线指数据以文件方式接入，不代表系统不提供在线 Web 服务。

VibraDiag 独立设计与开发。开源调研作为选型参考；复用的具体代码需单独验证并保留来源与许可证，不整体继承候选项目。

## 2. 目标用户与角色

| 角色 | 说明 | 主要使用界面 |
| --- | --- | --- |
| 维修工程师／振动分析人员 | 核对输入条件、查看分析与证据、复核报告与维修建议 | 诊断工作台，首发主用户 |
| 点检员 | 上传已有采集文件、补充设备与工况信息、描述现象 | 数据导入与对话窗口 |
| 设备主管 | 查看已复核报告与工单，按权限确认处理 | 报告与工单列表 |
| 系统管理员 | 管理账号、模型配置、部署、备份与审计访问 | 管理设置 |

客户形态：单工厂、单组织部署；首期采用少量授权用户的受控试用。并发容量与数据量在需求和版本计划中明确，不提前声称支持 10–30 人同时诊断。组织隔离方式在总体设计中确定，不做租户管理与计费。

## 3. 设备范围

- 首发目标设备：稳态、定速运行电机的滚动轴承；支持转速范围由所选算法与验证数据明确。
- 首发诊断假设：内圈、外圈、滚动体故障；同时允许“未发现支持上述故障的证据”“存在异常但类型无法确定”。后者不等同于正常或健康证明。
- 首发输入：单测点、单方向、均匀采样的加速度 CSV 文件；第一版确定支持 CSV，其他格式通过后续适配器扩展。采样率和加速度单位须在导入时填写或从可靠元数据读取，不采用未经确认的默认值。
- 分析条件：采样率、加速度单位必须明确；轴承频率匹配需要可靠转速及轴承参数或频率系数。负载、测点、方向与采集时间按任务要求补充，缺失信息不默认捏造。
- 首发不覆盖：保持架故障定类、变速阶次诊断、齿轮箱、汽轮机、往复机械、电气故障、多故障可靠分离与剩余寿命预测。
- 离心泵和其他设备暂列后续扩展，不在首发已验证能力内。

设备与部件不绑定厂家。系统支持实际文件接入；当前开发验证来源为公开试验数据和明确标识的仿真异常案例。

数据覆盖先建立文件级清单，不承诺不存在的数据组合：

| 维度 | 取值 |
| --- | --- |
| 故障类型 | CWRU 正常、内圈、外圈、滚动体，以实际标签为准 |
| 损伤尺寸 | 保留原始英寸标注；正常样本不适用，不推断现场损伤尺寸 |
| 工况 | 保留实际转速和负载，不以数据集编号代替真实工况 |
| 故障位置与测点 | 故障安装位置与采集通道分别记录，不混为同一维度 |

主线先使用 CWRU；外部验证优先评估 Paderborn，趋势回放后续评估 IMS。各来源按任务与标签分别评测，未经适配的数据不强行合并。数据使用条件与来源在需求和评测方案中记录。

## 4. 三个核心场景

1. 文件诊断：导入数据并描述现象 → 核对设备、测点与工况 → 质量和适用性检查 → 工具分析 → Agent 按假设取证 → 输出受支持的判断或说明无法确定。
2. 证据化复核：展示原始片段、处理配置、特征与频谱、支持与反对证据、缺失信息与建议；工程师复核后发布报告。适用条件不足时不强行进行标准分级。
3. 内部工单与复测：人工确认具体报告版本和动作 → 创建内部工单 → 记录执行与复测 → 对比条件相容的数据。维修事实由人员记录；单次振动下降不能自动证明维修有效。

## 5. 成功指标与试用准入

下列算法指标是开发目标，不是已取得结果，也不替代现场验收。最终样本数量、切分清单、硬件、数据长度、模型及统计方法在版本计划和评测方案中确定。

| 指标 | 目标 | 口径 |
| --- | --- | --- |
| 主线诊断准确率 | 暂定 ≥ 0.85 | CWRU 四类；按原始记录分组后切窗；测试集拒答计入未判对，另报已回答准确率和回答覆盖率 |
| 正常误报率 | 暂定 ≤ 8% | 正常样本被判为上述故障的比例；同时报告正常样本拒答率 |
| 证据引用完整率 | 100% | 发布的诊断判断必须引用可解析到源文件、处理配置与具体分析结果的证据；引用完整不等于判断正确 |
| 无有效证据时输出确定性诊断 | 验收案例中为 0 | 无效引用、缺少任务必要条件和冲突未解时，不发布确定性故障判断 |
| 应拒答案例识别率 | 暂定 ≥ 0.90 | 应拒答案例中正确拒答的比例；同时报告可回答案例的错误拒答率，防止全部拒答 |
| 自动分析与诊断时延 | 暂定 P95 < 30s | 从已上传且必要信息齐全的任务受理到结果完成，含排队、读取、工具与模型调用；不含人工补充等待 |
| 资源与调用成本 | 明确限额并可观测 | 模型输入输出 token、工具次数、超时、重试及降级均记录；阈值在版本计划确定 |

受控试用版本还必须完成：

- 内网部署与重启恢复，明确模型本地运行或获准调用外部服务的配置，不擅自外发文件。
- 账号与角色权限、文件访问控制、输入校验、原文件保留、报告版本和追加式审计。
- 工单人工确认与幂等；失败状态可见，不用假成功或假诊断掩盖依赖故障。
- 备份与恢复演练、运行日志与健康检查、安装升级和回退说明。
- 提供适用设备及数据条件清单、已知限制、操作说明和可复现验收记录。

具体工厂试用前，需按设备、传感器和采集条件做适用性核对，并以该现场的验收结果决定是否扩大使用范围。

## 6. 范围边界

做：
- 离线振动文件接入、质量检查、多轮澄清、工具取证、诊断推理与拒答、证据报告、人工复核建议、内部工单、审计、评测，以及试用所需部署与运行保障。

不做：
- 实时采集与在线监测、PLC/SCADA/MES 集成、产线联动
- 自动停机、自动派工、自动采购备件
- 齿轮箱、汽轮机等复杂设备
- 大模型训练与微调（优先特征工程、规则及可独立验证的分类基线；是否训练轻量分类器在总体设计中决定）
- 多租户 SaaS、计费、自助注册

## 7. 差异化

1. 诊断循环：多假设生成 → 必要证据检查 → 按需调用工具 → 冲突检查 → 收敛或拒答，保留实际工具轨迹。
2. 证据链：判断可回溯到文件校验值、信号片段、单位、工况和算法配置；知识引用保留来源及版本。
3. 计算与解释分离：FFT、包络谱与特征频率由代码计算，模型组织分析并解释工具结果，不自行编造数值。标准评估先核对适用条件，和轴承故障、维修优先级分别表达。
4. 评测闭环：记录级隔离的数据划分、异常案例、失败分析和可复现实验，分别评价工具、Agent 与业务链路。

## 8. 关键约束

- 数据：公开文件有来源、校验值、元数据与使用条件；仿真案例注明生成方法和目的，不替代现场效果验证。
- 技术方向：Python 分析服务、FastAPI、LangGraph、Web 工作台；数据库、前端框架和缓存按需求在总体设计中选定，避免提前堆叠组件。
- 模型：通过适配层接入云端 API 或本地模型；无模型配置时可运行数值分析，不能伪装为真实 Agent 诊断成功。mock 仅用于标识清楚的开发测试。
- 部署：目标为 Docker Compose 单机部署，支持数据持久化、配置检查和受限网络环境；容量边界需实测。
- 人工控制：停机、拆机和维修实施由有权限的人员决定；建议需工程师复核，工单写入绑定已确认版本与动作并具备幂等性。
