# 00 项目定义卡

> 版本：v1.0（已冻结）
> 状态：第 1 步产出物
> 项目名：VibraDiag
> 中文名：旋转机械振动故障诊断 Agent（滚动轴承方向）
> 界面名：设备听诊台
> 上游：无
> 下游：01-requirements.md

## 1. 一句话定位

面向中小制造企业设备运维的振动故障诊断助手：运维人员用自然语言描述现象，系统拉取振动数据、计算特征、生成故障假设并逐条取证，输出带证据链的诊断结论与维修建议，人工确认后才生成工单。

## 2. 目标用户与角色

| 角色 | 说明 | 主要使用界面 |
| --- | --- | --- |
| 点检员 | 现场采集振动数据、描述异常现象 | 对话窗口 |
| 维修工程师 | 查看诊断结论与证据，决定维修动作 | 诊断工作台 |
| 设备主管 | 审批高优先级工单、查看设备健康趋势 | 设备总览与工单 |

客户形态：单个工厂的设备运维团队，10–30 人，单租户运行。数据库保留 `tenant_id` 做行级隔离，不做租户管理与计费。

## 3. 设备范围

- 设备类型：旋转机械，首发覆盖三相异步电机与离心泵
- 监测对象：滚动轴承（内圈、外圈、滚动体、保持架）
- 工况维度：转速、负载、采样频率、测点位置
- 明确不覆盖：齿轮箱、汽轮机、往复机械、电气故障

设备与部件写类型，不绑定任何厂家品牌；数据来源为公开数据集，不声称来自真实工厂。

数据覆盖按四个维度做满：

| 维度 | 取值 |
| --- | --- |
| 故障类型 | 正常、内圈、外圈、滚动体 |
| 损伤程度 | 0.007 / 0.014 / 0.021 英寸 |
| 工况 | 0 / 1 / 2 / 3 hp 负载 |
| 测点 | 驱动端、风扇端 |

外部验证使用 PHM 2012 轴承部分，仅作泛化参考，不进入主线指标分母。

## 4. 三个核心场景

1. 现象诊断：自然语言描述 → 多轮澄清（设备、测点、时间窗、工况）→ 拉数取证 → 诊断结论。
2. 证据化报告：现象、数据、特征、证据链、结论、维修建议、紧急程度，每条结论绑定证据 ID。
3. 工单闭环：人工确认 → 生成维修工单 → 审计留痕 → 维修后复测对比。

## 5. 成功指标

| 指标 | 目标 | 口径 |
| --- | --- | --- |
| 端到端诊断 Top-1 准确率 | ≥ 0.85 | 凯斯西储留出集，正常 + 内圈 + 外圈 + 滚动体四类 |
| 正常误报率 | ≤ 8% | 正常样本被判为故障的比例 |
| 证据覆盖率 | 100% | 每条诊断结论必须绑定证据 ID |
| 无证据结论率 | 0 | 证据不足时只能拒答，不得下结论 |
| 拒答准确率 | ≥ 0.90 | 证据不足样本中正确拒答的比例 |
| 诊断时延 | P95 < 30s | 不含数据加载，含多轮工具调用 |
| 单次诊断 token | ≤ 8k | 输入加输出，超限触发降级 |

## 6. 范围边界

做：
- 离线振动数据分析、多轮澄清、工具取证、诊断推理、证据链报告、维修建议、人工确认工单、审计、评测。

不做：
- 实时采集与在线监测、PLC/SCADA/MES 集成、产线联动
- 自动停机、自动派工、自动采购备件
- 齿轮箱、汽轮机等复杂设备
- 模型训练与微调（使用现成特征工程 + 分类工具 + 规则）
- 多租户 SaaS、计费、自助注册

## 7. 差异化

1. 诊断循环：多假设生成 → 逐条取证 → 冲突排除 → 收敛或拒答，不是「查一次写报告」。
2. 证据链：结论绑定证据 ID，证据可回溯到原始信号片段与标准条款。
3. 计算与解释分离：FFT、包络谱、特征频率、ISO 10816 分级全部由代码完成，模型无计算权限。
4. 评测闭环：金标集 + 消融（纯规则 / 纯模型 / 混合），指标可复现。

## 8. 关键约束

- 数据：凯斯西储大学轴承数据集（公开）；PHM 2012 仅作泛化验证，不参与主线指标。
- 技术栈：FastAPI + LangGraph（PostgresSaver）+ PostgreSQL + pgvector + Redis；前端 Vue3 + Element Plus + ECharts。
- 模型：兼容 DeepSeek / Qwen API 与本地 Ollama；无 Key 时 mock 模式可完整跑通链路。
- 部署：Docker Compose 一键启动，单机可运行。
- 安全：模型不参与停机与拆机决策；工单写操作必须人工确认并带幂等键。
