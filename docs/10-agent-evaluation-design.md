# 10 Agent对照评测设计

> v0.7；2026-11-01。T05d本机证据收口，受限软件有条件通过；完整语义/诊断及工厂资格仍未通过。

## 1. 先回答什么

比较当前正式数值链路的规则、单次模型路由及逐步Agent，在相同授权输入、确定性工具和条件检查下能否完成指定任务，是否在缺确认时正确挂起、是否保留真实来源及资格缺项。旧benchmark_agent.py为M0历史原型，结果不纳入正式链路对照。

## 2. 三组定义

| 组别 | 执行方式 | 模型开销 |
| --- | --- | --- |
| rules | 原有持久规则图 | 0 |
| single_router | 一次选择已登记的完整规则工作流、仅基础分析工作流或拒答，随后按规则执行 | 最多1次，确认不足时0次 |
| agent | T04b2正式数值模型图，每轮读取当前结果及候选 | 当前图最多6次，确认不足时0次 |

单次模型基线是“单次路由+规则工作流”，不是任意单提示模型的能力上界。模型看到的候选粒度不同，本实验比较这三个具体实现，不证明所有Agent都优于单次模型。完整工作流与仅基础分析只在轴承任务同时提供，模型不能发送参数。单次路由适配器只用于离线评测，不注册生产执行器或公共API；其模型预留进入任务预算，真实调用另存私有回执与审计事件，生产model_called字段仍只统计正式模型轮账本，报告另合并路由回执，不能漏计或冒称正式图模型调用。

## 3. 冻结任务与数据

协议[agent-evaluation-v1.json](../backend/config/agent-evaluation-v1.json)公开5个开发控制用例：基础分析、缺几何不确定量的轴承观察、不确定量完整的轴承观察、未确认输入、恶意指令描述。目标字段是显式结构化输入，本轮不评测自然语言目标分类。

用例采用同一自编AM信号族及解析几何，都是synthetic，不是5条独立采集、更不是现场故障样本。每个用例独立资产/输入，三组在该用例共用相同输入和确认、各自重算工具，不复制其他组结果。未做随机留出，作者可见全部预期，不能计算工厂准确率或统计置信区间。预期动作和状态不发送给模型，模型只见问题、工作流/当前候选及必要摘要。

配置、源码、协议、测试回执在首个真实调用前写入带hash的冻结清单；运行结束再次校验源码指纹。只运行1遍，按用例序号轮换三组顺序，顺序执行、不并发，不自动修复输出、重试供应商或切换模型。失败如实保留，后续迭代须新增协议/回执版本，不能覆盖首轮观察。

## 4. 指标与边界

- 预期满足：任务状态、工具动作及重复次数、引用要求、确认前挂起与诊断资格缺项均满足开发者预设；工具覆盖不等于故障准确率。
- 引用链接有效：basic_analysis/tool_run必须出自本任务真实已完成来源，当前草稿可用；没有引用的拒答不能计为可引用回答。只验证链接与可用性，不验证相关性或文本语义。
- 挂起正确：缺输入确认必须在任何模型预算和工具调用前挂起。
- 运行开销：任务创建至最终查询的壁钟时间、实际工具次数、预留/确认/未知模型次数与供应商token回执。缺用量为null，不按0计算。
- 金额成本：没有绑定日期的价格表或供应商账单，货币成本为null。token数不能直接写成节省费用百分比。

单次路由完整工作流和规则组可能得到完全相同结果，Agent也可能只增加调用和耗时，应据实报告。无预热、单次顺序运行、存在缓存与负载干扰，耗时仅描述本轮，不排名供应商或宣称性能优势。固定安全用例通过不等于全面对抗评测通过。方法/RAG、比较声明和本地模型不在本轮覆盖范围。

## 5. 执行与交付

使用专用测试数据库、隔离数据目录和单个ASGI应用租约，真实PostgreSQL/文件/生产数值子进程；HTTP路由通过进程内ASGI客户端调用，不把它写成网络部署或工厂上线。测试必须先通过、退出后才能运行真实对照。

~~~bat
.venv\Scripts\python.exe backend\scripts\benchmark_formal_agent.py --allow-paid-model-calls
~~~

命令还要求已有外发许可及私有DeepSeek key。本轮显式使用DeepSeek固定配置；本地T04b1拒答记录保留，不将其失败纳入本轮云端成功率分母。结果见[T05a验收](acceptance/M3-T05a-verification.md)。运行源码无需生产迁移，业务表仍44张、检查点4张。
