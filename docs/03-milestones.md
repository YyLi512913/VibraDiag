## 1. 推进原则

- 先证明分析与Agent能力，再完善业务闭环；仅做必要的数据、权限和执行基础，不先开发通用后台管理平台。
- 每阶段遵循详细设计 → 实现 → 工具/接口测试 → 真实链路验证 → 验收记录。上一阶段存在影响正确性或数据边界的阻塞项时，不用增加页面掩盖问题。
- 最终试用版须满足需求中的全部P0；中间版可以不完整，但显著标明能力边界。既有实验原型的通过记录不能自动替代新实现的验收。
- 按交付条件安排顺序，不先承诺未经估算的日期。数据库迁移、算法实现和评测工作量明确后再给时间估计。
- 每阶段保留代码/配置版本、测试输入清单、期望/实际结果、失败及修复记录。不把“模型返回了文字”“HTTP200”当诊断正确或工单完成。
- 工程师/主管权限、原文件不可变、事实来源、配置版本与审计从相关模块首次实现时纳入；完整管理页面可以后置，隔离规则不能最后临时补。

### 4.2 验收门槛

- M1-AT01：合法CSV与已知正弦、DC偏置、g换算、奇偶长度/Nyquist、零/常值/冲击数值验证；各指标容差在实现前固定。
- M1-AT02：非法编码/表头/空行、非数值、NaN/Inf、错误采样率/单位、过短/超限输入明确失败，没有空成功或危险路径写入。
- M1-AT03：相同内容和不同参数版本可追溯；重启后读取原记录，修订不覆盖旧分析；受控损坏/缺失文件被识别。
- M1-AT04：至少两个账号的授权/未授权和未关联文件访问检查；后端拒绝越权，非仅前端隐藏。
- M1-AT05：真实前后端导入/图表链路、数据库重建/迁移和原始文件清单可复现；初测典型120000点分析耗时并保留失败计数。

退出交付已形成：设计、迁移、接口、身份范围、正式前端、测试/浏览器及性能基线。**M1-T01—T05与本机阶段验收通过，见[M1记录](acceptance/M1-acceptance.md)；下一步M2-T01。**
